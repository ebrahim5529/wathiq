# ملف تحليل كامل — نظام الأرشفة

**المشروع:** HR / نظام الأرشفة  
**التقنية:** ASP.NET Core MVC + Entity Framework Core + AdminLTE 4  
**مرجع الواجهة:** `adminite/pages/file-manager.html`  
**مرجع الواجهة:** `adminite/

**تاريخ الإعداد:** 2026-11-02  
**الحالة الحالية:** واجهة مدير الملفات + قوائم جانبية (تصميم فقط)

---

## 1. هدف النظام

بناء نظام أرشفة إلكتروني لإدارة الملفات والمجلدات والمستندات الرسمية، مع تصنيف، أقسام، صلاحيات، بحث، تقارير، ومسار تدقيق (Audit Trail).

---

## 2. المستخدمون والأدوار المقترحة

| الدور | الوصف | صلاحيات أساسية |
|------|--------|----------------|
| مدير النظام | كامل الصلاحيات | كل الشاشات + الإعدادات + المستخدمون |
| أمين الأرشيف | إدارة المحتوى | رفع / نقل / تصنيف / استعادة / تقارير |
| مشرف قسم | نطاق قسمه فقط | عرض + رفع + مشاركة داخل القسم |
| مستخدم | استخدام يومي | عرض المسموح + رفع محدود + مفضلة |
| ضيف / قراءة فقط | اطلاع | عرض وتنزيل حسب المشاركة |

## 4. تفصيل كل قائمة وشاشة

### 4.1 لوحة التحكم (`Dashboard`)

**المسار المقترح:** `/Dashboard`  
**Controller:** `DashboardController`  
**الهدف:** نظرة عامة سريعة على حالة الأرشيف.

| العنصر | التفاصيل |
|--------|----------|
| بطاقات إحصائية | إجمالي الملفات، المجلدات، حجم التخزين، المرفوع اليوم |
| رسوم | مرفوعات آخر 7/30 يوم، توزيع حسب النوع/القسم |
| قوائم | أحدث الملفات، أكثر الملفات مشاهدة، تنبيهات انتهاء عقود |
| اختصارات | رفع ملف، مجلد جديد، بحث متقدم |

**حقول/بيانات مصدرها:** تجميعات من `ArchiveItems` + `ActivityLogs` + `StorageUsage`.

**أولوية التنفيذ:** متوسطة (بعد مدير الملفات).

### 4.2 مدير الملفات (`File Manager`) — الشاشة الحالية

**المسار:** `/` أو `/Archive`  
**Controller:** `ArchiveController` / حالياً `HomeController`  
**مرجع التصميم:** File Manager في Adminite.

#### مكونات الواجهة
1. **شجرة المجلدات (يسار):** أرشيفي، مجلدات فرعية، مشارك معي، مفضلة، أخيرة، سلة.
2. **أزرار:** رفع ملفات، مجلد جديد.
3. **شريط علوي:** مسار المجلد (Breadcrumb)، بحث سريع، تبديل عرض شبكة/قائمة.
4. **منطقة المحتوى:** بطاقات مجلدات/ملفات أو جدول قائمة.
5. **بطاقة التخزين:** نسبة الاستخدام من الحصة.

#### العمليات المطلوبة

| العملية | الوصف | ملاحظات |
|---------|--------|---------|
| إنشاء مجلد | اسم + مجلد أب اختياري | منع التكرار في نفس المستوى |
| رفع ملفات | متعدد، Drag & Drop | أنواع/حجم أقصى من الإعدادات |
| فتح مجلد | تصفح المحتوى | تحديث الشجرة والمسار |
| تنزيل | ملف واحد أو ZIP لمجلد | صلاحية تنزيل |
| إعادة تسمية | ملف/مجلد | تحديث الاسم المعروض فقط |
| نقل / نسخ | إلى مجلد آخر | التحقق من الصلاحيات |
| مشاركة | مستخدمين/أقسام + صلاحية | قراءة / تنزيل / تعديل |
| حذف ناعم | إلى السلة | Soft Delete |
| تفضيل | إضافة/إزالة نجمة | لكل مستخدم |

#### بيانات العرض لكل عنصر
- الاسم، النوع (مجلد/امتداد)، الحجم، تاريخ التعديل، شارة مشاركة، أيقونة حسب الامتداد.

**أولوية التنفيذ:** عالية جداً (الأساس).

### 4.3 بحث متقدم (`Advanced Search`)

**المسار:** `/Search`  
**Controller:** `SearchController`

| معيار البحث | النوع |
|-------------|------|
| كلمة في الاسم / الوصف | نص |
| رقم الأرشيف / المرجع | نص |
| التصنيف | قائمة |
| القسم | قائمة |
| نوع المستند | قائمة (رسمي، عقد، مراسلة، فاتورة، عام) |
| امتداد الملف | قائمة أو متعدد |
| تاريخ الرفع / من–إلى | تاريخ |
| رفع بواسطة | مستخدم |
| الوسوم (Tags) | متعدد |
| داخل سلة المحذوفات؟ | نعم/لا |

**النتائج:** جدول + إمكانية فتح في مدير الملفات / تنزيل / إضافة للمفضلة.

**أولوية:** عالية.

### 4.4 الأرشيف — الفروع حسب النوع

كلها تعتمد على نفس محرك القائمة مع **فلتر نوع المستند** (`DocumentType`).

| القائمة | DocumentType | حقول إضافية مقترحة |
|---------|--------------|---------------------|
| كل الملفات | الكل | — |
| المستندات الرسمية | Official | رقم صادر/وارد، جهة الإصدار |
| العقود | Contract | رقم العقد، الطرف الثاني، تاريخ البداية/الانتهاء، تنبيه قبل الانتهاء |
| المراسلات | Correspondence | وارد/صادر، الجهة، رقم الخطاب |
| الفواتير | Invoice | رقم الفاتورة، المبلغ، العملة، تاريخ الاستحقاق |

**المسار:** `/Archive?type=Contract` إلخ.  
**Controller:** `ArchiveController` بإجراء `Index(string? type, int? folderId)`.

**أولوية:** عالية (بعد الملفات العامة).

### 4.5 التصنيفات (`Categories`)

**CRUD كامل.**

| الحقل | مطلوب | ملاحظات |
|------|--------|---------|
| الاسم | نعم | فريد |
| الوصف | لا | — |
| اللون / أيقونة | لا | للعرض في البطاقات |
| التصنيف الأب | لا | شجرة اختيارية |

**قواعد:** لا حذف تصنيف مرتبط بملفات إلا بعد إعادة التعيين أو التعطيل.

**أولوية:** عالية.

### 4.11 التقارير

#### أ) إحصائيات الأرشيف
- عدد الملفات حسب النوع / القسم / التصنيف / الشهر.
- تصدير Excel/PDF.

#### ب) سجل النشاط (Audit Log)
| الحقل | مثال |
|------|------|
| المستخدم | أحمد |
| الإجراء | Upload / Download / Delete / Share / Rename |
| العنصر | design-review.pdf |
| التاريخ والوقت | — |
| عنوان IP | اختياري |

#### ج) التخزين المستخدم
- إجمالي الحجم، حسب المستخدم/القسم، الحصة والحد الأقصى، نسبة الامتلاء.
- تنبيه عند تجاوز نسبة (مثلاً 80%).

**المسار:** `/Reports/...`  
**Controller:** `ReportsController`  
**أولوية:** متوسطة (بعد استقرار البيانات).

### 4.13 الصلاحيات (`Roles & Permissions`)

**المسار:** `/Roles`  
**مستويان:**

1. **صلاحيات النظام (شاشات):** من يرى لوحة التحكم، المستخدمين، التقارير...
2. **صلاحيات المحتوى (على مجلد/ملف/قسم):**

   - إدارة

**أولوية:** عالية بالتوازي مع المستخدمين.

## 7. خطة التنفيذ على مراحل

### المرحلة 1 — الأساس (أسبوع 1)
1. إعداد EF Core + Connection String + Migration أولى.
2. نماذج: Folder, File, Category, Department.
3. تفعيل وظائف مدير الملفات: إنشاء مجلد، رفع، تصفح، تنزيل، حذف ناعم.
4. ربط القائمة الجانبية بالمسارات الحقيقية.

### المرحلة 2 — التنظيم والبحث (أسبوع 2)
1. CRUD التصنيفات والأقسام.
2. أنواع المستندات (رسمي/عقود/مراسلات/فواتير) + حقول إضافية.
3. البحث المتقدم.
4. المفضلة + الأخيرة + السلة (استعادة/حذف نهائي).

### المرحلة 3 — الأمان والمشاركة (أسبوع 3)
1. Identity: تسجيل دخول / مستخدمون / أدوار.
2. صلاحيات الشاشات والمحتوى.
3. المشاركة معي.
4. سجل النشاط الأساسي.

### المرحلة 4 — التقارير والإعدادات (أسبوع 4)
1. لوحة التحكم.
2. التقارير الثلاثة.
3. شاشة الإعدادات.
4. تحسينات UX (Drag & Drop، معاينة PDF/صور، إشعارات).

## 9. معايير القبول العامة لكل شاشة

- تظهر في القائمة الجانبية وتكون مميزة عند التفعيل (active).
- تحترم صلاحية الدور (إخفاء أو رفض 403).
- رسائل نجاح/خطأ بالعربية.
- لا تكسر تصميم AdminLTE الحالي.
- العمليات الحساسة تُسجَّل في سجل النشاط.

## 11. قرار مطلوب من صاحب المشروع قبل البدء

1. **قاعدة البيانات:** ✅ تم اختيار **MySQL** (`MySql.EntityFrameworkCore` + قاعدة `HR_Archive`)
2. **هل يلزم تسجيل دخول من المرحلة 1 أم لاحقاً؟**
3. **حجم الرفع الأقصى** والأنواع المسموحة؟
4. **هل العقود تحتاج تنبيهات انتهاء إلزامية؟**
5. **هل الأرشيف متعدد الشركات (Multi-tenant) أم جهة واحدة؟**
